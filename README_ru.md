# GateHouse — генератор конфига sing-box и его веб-редактор

Этот репозиторий содержит инструмент, который превращает подписку из VLESS-ссылок
вместе с файлом настроек в `config.json` для sing-box, и браузерный редактор,
который этими настройками управляет. Работа разбита на три этапа:

* **этап 1 — ядро генерации** ([`src/core/`](src/core/settings.mjs:1)): чтение
  настроек, разбор VLESS-ссылок, валидация и сборка `config.json`,
  **побайтово совпадающего** с выводом эталонной питоновой реализации
  ([`SingBoxTools/sing_box_manager.py`](https://example.invalid/SingBoxTools/sing_box_manager.py)).
* **этап 2 — веб-редактор** ([`src/model/`](src/model/project.mjs:1),
  [`src/web/`](src/web/app.mjs:1), [`views/`](views/layout.ejs:1),
  [`public/`](public/app.css:1)): сервер на Express, который показывает настройки
  деревом и формами, сохраняет `webui.json` атомарно со снапшотами и генерирует
  `config.json` для активного профиля. По функциям это замена Qt-GUI питонового
  проекта.
* **этап 3 — всё, что трогает систему**: `sing-box check`, перезапуск демона и
  откат, снимок журнала, тест серверов, geosite, systemd-юнит, права, деплой и
  аутентификация. Реализовано: [`src/system/index.mjs`](src/system/index.mjs:1) —
  единственный модуль, который запускает команды, и всегда через `execFile`/`spawn`
  с массивом аргументов. [`deploy/`](deploy/README.md:1) содержит юнит, правило
  sudoers, вариант на polkit и порядок развёртывания — файлами, готовыми к
  применению.
* **продолжение — закреплённый выход и сторож связи**: флаг `pinned` у прокси
  запрещает пул, а сторож проверяет каждый прокси с `watch: true` через его
  инбаунд, после неудачи закрывает соединения только этого прокси и — лишь при
  включённой второй ступени — перезапускает демон. Реализовано:
  [`src/watchdog/watchdog.mjs`](src/watchdog/watchdog.mjs:1) и
  [`src/watchdog/clash.mjs`](src/watchdog/clash.mjs:1).

Ядро — порт, а не переписывание. У эталона три года эксплуатации и 79 тестов,
поэтому первым делом точное совпадение, а не улучшения. Всё, что в эталоне
выглядит странно, описано в
[`techdocs/done_2026_09_14_port_core_generator.md`](techdocs/done_2026_09_14_port_core_generator.md),
а не «поправлено» по дороге. Веб-редактор описан в
[`techdocs/done_2026_09_14_web_editor.md`](techdocs/done_2026_09_14_web_editor.md),
а системный слой — в
[`techdocs/done_2026_09_14_system_integration.md`](techdocs/done_2026_09_14_system_integration.md).

## Требования

* Node **22** (мажорная версия закреплена в `.nvmrc`; проверено на 22.23.2 с
  npm 10.9.8 — те же версии, что на роутере)
* npm — рантайм-зависимости: `ajv`, `express` и `ejs`

## Установка и тесты

```bash
npm ci          # рантайм: ajv, express, ejs; dev: htmx.org
node --test     # без сети, root и sing-box
npm run dev     # морда против песочницы dev/, не против роутера
```

Тесты системного слоя запускают скрипты-обманки из `tests/fixtures/bin/` вместо
`sing-box`, `systemctl` и `journalctl`: набор не трогает ни живой демон, ни
роутер, ни `sudo`.

`node --test` находит `tests/*.test.mjs` и создаёт все временные файлы в
системном каталоге временных файлов: прогон никогда не трогает репозиторий,
рабочий `webui.json` или `config.json`. HTTP-тесты поднимают редактор на порту
`0` и общаются с ним через `fetch`, поэтому порт у работающего экземпляра
никогда не занимается.

Закоммиченный [`.npmrc`](.npmrc:1) задаёт `maxsockets=2`: реестр отвечает
быстро, но достаточно медленно, чтобы холодный `npm ci` на дефолтных 15
параллельных сокетах уходил в `ETIMEDOUT` — и здесь, и на роутере. После одной
удачной установки `npm ci --prefer-offline` не требует сети вовсе.

`public/vendor/htmx.min.js` закоммичен сознательно (см. заметку «без CDN» ниже)
и обновляется из dev-зависимости `htmx.org`:

```bash
npm run vendor:htmx                  # скопировать закреплённую сборку в public/vendor/
node tools/vendor-htmx.mjs --check   # упасть, если закоммиченная копия устарела
```

## Разработка без роутера

`npm run dev` поднимает редактор против песочницы в `dev/`, поэтому работа над
мордой не трогает живой роутер:

```bash
npm run dev      # http://127.0.0.1:9091/
```

`dev/bin/systemctl` и `dev/bin/sudo` — заглушки: они печатают полученные
аргументы и выходят с кодом 0, ничего на машине не меняя. `sing-box` остаётся
настоящим, потому что `check` и `tools fetch` должны вести себя ровно как на
роутере. Морда определяет, что её пути ведут внутрь `dev/`, и показывает метку
«песочница» в заголовке страницы, поэтому экземпляр разработки нельзя перепутать
с боевым.

Данные песочницы (`dev/root/`) в репозиторий сознательно не попадают — в них
ключи и личные списки серверов. Обезличенные образцы лежат в `dev/root.example/`:

В наборе образцов есть и файл ссылок; без него все сервера всех прокси считаются
пропавшими — копировать надо все три:

```bash
mkdir -p dev/root/etc/sing-box
cp dev/root.example/webui.json                dev/root/webui.json
cp dev/root.example/etc/sing-box/config.json  dev/root/etc/sing-box/config.json
cp dev/root.example/links.txt                 dev/root/links.txt
```

### Работа на боевых данных

Образцов хватает, чтобы запустить редактор, но в них три синтетических сервера.
Чтобы разрабатывать на том, что реально крутится на роутере, надо перенести его
файлы. Важно, где они лежат: настройки — в `/etc/`, а в `/var/lib/` только
снимки и списки серверов.

```bash
mkdir -p dev/root/sources/vpnd dev/root/etc/sing-box
scp denis@10.95.2.1:/etc/gatehouse/webui.json          dev/root/
scp denis@10.95.2.1:/etc/sing-box/config.json          dev/root/etc/sing-box/
scp denis@10.95.2.1:/var/lib/gatehouse/sources/vpnd/links.txt  dev/root/sources/vpnd/
```

**После этого в скопированном `webui.json` надо переписать `output_file`.** На
роутере он абсолютный, а разрешается относительно каталога с файлом настроек —
поэтому абсолютный `output_file` заставит песочницу целиться в настоящий
`/etc/sing-box/config.json` машины:

```json
"sources": ["vpnd"],
"output_file": "etc/sing-box/config.json"
```

`sources` содержит имена ПАПОК-провайдеров и разрешается от `GATEHOUSE_SOURCES`
(по умолчанию `dev/root/sources`), поэтому переписывать его не нужно, пока папка
лежит там.

Править **при остановленном сервере**. Он держит настройки в памяти и записывает
их обратно при сохранении, так что правка под работающим экземпляром пропадёт
при первом же сохранении.

### Сверка песочницы с боевым конфигом

Когда боевые данные на месте, генератор обязан воспроизвести тот конфиг, который
роутер крутит прямо сейчас, — байт в байт. Это самая сильная из доступных
проверок того, что правка модели или генератора не сдвинула вывод:

```bash
cp dev/root/etc/sing-box/config.json /tmp/live-config.json
node tools/generate.mjs --settings dev/root/webui.json --quiet
cmp /tmp/live-config.json dev/root/etc/sing-box/config.json && echo identical
```

Это ручная проверка, а не часть `node --test`: `dev/root/` в репозиторий не
попадает, и гонять её набору тестов не на чем. Автоматическим гейтом остаётся
золотой файл, собранный из закоммиченных фикстур, — см. «Приёмка по золотому
файлу».

### Одна вкладка за раз

Редактор держит документ в процессе сервера, а не в браузере. Две открытые
вкладки затирают правки друг друга. Dev-сервер говорит об этом при запуске; это
не ограничение песочницы, а устройство редактора.

## Использование

```bash
# собрать config.json рядом с webui.json
node tools/generate.mjs --settings webui.json

# переопределить вывод, один файл ссылок или адрес прослушивания
node tools/generate.mjs --settings webui.json \
    --output /etc/sing-box/config.json \
    --links tests/fixtures/sources/vpnd/links.txt \
    --listen-ip 10.95.2.1
```

| Флаг | Смысл |
| --- | --- |
| `--settings PATH` | файл настроек, по умолчанию `webui.json` |
| `--output PATH` | куда писать `config.json` (переопределяет `output_file`) |
| `--links PATH` | прочитать один файл ссылок вместо папок `sources` |
| `--listen-ip IP` | адрес прослушивания (переопределяет `listen_ip`) |
| `--exclude-from-auto PREFIX...` | префиксы тегов, выкидываемые из `auto-select` |
| `--warnings-file PATH` | записать собранные предупреждения в JSON |
| `--quiet` | не печатать сводку |

Относительные пути внутри файла настроек резолвятся относительно каталога этого
файла, поэтому утилиту можно запускать из любого рабочего каталога. Код возврата
0 при успехе и 1 при любой ошибке конфигурации, причина — в stderr.

## Веб-редактор

```bash
npm start        # Веб-редактор webui.json: http://127.0.0.1:8080/
```

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `GATEHOUSE_SETTINGS` | `webui.json` | файл настроек; если его нет, создаётся первым сохранением |
| `GATEHOUSE_HOST` | `127.0.0.1` | адрес прослушивания. Не адрес петли **требует** токена, см. «Аутентификация» ниже |
| `GATEHOUSE_PORT` | `8080` | порт; `0` выбирает свободный |
| `GATEHOUSE_STATE_DIR` | `./.state` | куда кладутся снапшоты; на роутере это будет `/var/lib/gatehouse` |
| `GATEHOUSE_TOKEN` | *(пусто)* | токен доступа. Обязателен, если адрес привязки не петля |

Системный слой читает свои переменные — тоже из окружения и никогда из запроса:

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `GATEHOUSE_SINGBOX` | `/usr/local/bin/sing-box` | бинарь для `check` и `tools fetch` |
| `GATEHOUSE_SYSTEMCTL` | `/usr/bin/systemctl` | `systemctl`; путь обязан совпадать с правилом sudoers |
| `GATEHOUSE_JOURNALCTL` | `/usr/bin/journalctl` | `journalctl` |
| `GATEHOUSE_CURL` | `/usr/bin/curl` | бинарь, которым сторож проверяет инбаунд |
| `GATEHOUSE_SUDO` | `/usr/bin/sudo` | `sudo`; значение `none` вызывает `systemctl` напрямую (вариант на polkit) |
| `GATEHOUSE_UNIT` | `sing-box` | имя юнита |
| `GATEHOUSE_CONFIG` | `/etc/sing-box/config.json` | конфиг по умолчанию для команд; из UI приходит сгенерированный путь |
| `GATEHOUSE_TEST_URL` | `https://ipinfo.io` | цель теста серверов |
| `GATEHOUSE_TEST_TIMEOUT` | `8000` | таймаут одной проверки, мс |
| `GATEHOUSE_TEST_CONCURRENCY` | `4` | сколько проверок идёт одновременно |
| `GATEHOUSE_API_SECRET` | *(пусто)* | секрет `experimental.clash_api`. **В `webui.json` не хранится**; без него генератор отказывается включать API |

Путь к файлу настроек берётся из окружения и больше ниоткуда. «Открыть файл» в
браузере нет сознательно: путь, приходящий из браузера в процесс, который пишет
файлы, — это готовый path traversal.

Экраны — по узлу дерева: Общие, Провайдеры (папки-источники и их туннели),
Вывод, Прокси → тег, Маршруты → имя, DNS, а под «Системой»: Журнал, Тест серверов,
Сторож. У конфига туннеля — отдельный экран предпросмотра нормализации.

* **`webui.json` плоский, уровень профилей упразднён.** Раньше тело делилось
  между активным профилем и `defaults`; профиль был ровно один, `defaults` пуст,
  и наследовать было некому. Формат `version: 2` — один уровень, «Общие» — одна
  панель. Файл старого формата редактор переводит сам: делает снимок, разворачивает
  единственный профиль (несколько — отказ с именами), заменяет `links_file` на
  `sources` и поднимает версию. Ядро старый файл не читает и говорит об этом, чтобы
  CLI не мигрировал его наполовину.
* **Источники — папки-провайдеры, а не один файл ссылок.** `sources` перечисляет
  имена папок под корнем (`GATEHOUSE_SOURCES`, по умолчанию
  `<каталог webui.json>/sources`); имя папки и есть имя провайдера. Папка держит
  `links.txt` (выходы), конфиги туннелей `*.conf` (только показываются) или и то,
  и другое. Ссылки сводятся в один список; **метка провайдера появляется только
  при совпадении имён у разных провайдеров**, поэтому при одном источнике теги не
  меняются и `config.json` остаётся побайтово прежним. Совпадение внутри одного
  файла — предупреждение: это ошибка провайдера, и владелец должен о ней узнать.
  На вкладке «Провайдеры» список редактируется строками: папка добавляется
  выбором из найденных под корнем, убирается кнопкой в своей строке; содержимое
  папок перечитывается при каждом открытии. Клик по имени провайдера открывает
  его содержимое: у папки со ссылками — список серверов, у папки с туннелями —
  список `.conf`, каждый открывается в предпросмотре. Ни одно действие не трогает
  файлы на диске: «убрать» значит «не читать», а не «удалить папку владельца».
* **Туннели в генерацию не попадают.** Нормализатор `src/core/normalize.mjs` —
  чистая функция: добавляет `Table = off`, убирает `DNS =`, следит за именем
  интерфейса ≤ 15 символов, а `AllowedIPs` и обфускацию (`Jc/Jmin/Jmax`, `S1–S4`,
  `H1–H4`, `i1`) копирует байт в байт. Экран — предпросмотр диффа с единственной
  галочкой (policy routing); обязательные правки галочек не получают, кнопки
  «применить» нет.
* **DNS — текстовое поле с JSON.** В sing-box 16 типов DNS-серверов, схема свежая
  и ещё движется, а правят DNS редко; проверяется только то, что это валидный
  JSON-объект. Структурные формы не делались сознательно.
* **Битая ссылка — пометка, а не ошибка.** Прокси, ссылающийся на сервер,
  пропавший из файла ссылок, и маршрут с неизвестным `outbound` помечаются в
  дереве; сохранять по-прежнему можно. Отказывается только генератор, и только
  на пул для отсутствующего сервера.
* **Список серверов сохраняет свой порядок.** Пикер рисует отмеченные серверы
  первыми, в том порядке, в каком они лежат в файле, а остальные серверы файла
  ссылок — после них. Браузер отправляет отмеченные галочки в порядке документа,
  поэтому при любой другой раскладке первое же сохранение нетронутой формы
  переписало бы список в порядок файла ссылок, а сервер, пропавший из файла
  ссылок, уехал бы в конец. Список — обычные галочки, поэтому он работает и с
  выключенным JavaScript; поле фильтра и кнопка «снять все» — это десяток строк в
  [`public/app.js`](public/app.js:1), которые строку только ПРЯЧУТ: галочка,
  вынутая из DOM, уехала бы из формы вместе со своим сервером. Рядом с каждой
  галочкой стоит пометка «в auto-select» или «исключён» по `exclude_from_auto`,
  так что решение «добавить сервер в пул» принимается там, где оно принимается.
* **Имена маршрутов не могут состоять только из цифр.** JavaScript переставляет
  целочисленные ключи объекта, поэтому маршрут с именем `2024` молча прыгнул бы в
  начало файла и порядок в секции `routes` файла `config.json` перестал бы быть
  предсказуемым. `2024-telegram` — нормально. Правило живёт в схеме;
  [`src/model/project.mjs`](src/model/project.mjs:1) его повторяет, а тест
  проверяет, что они не разошлись.
* **Запись атомарная и версионированная.** Предыдущая версия копируется в
  `<state-dir>/snapshots/webui-<ISO>.json` (хранятся последние 10), и только потом
  новая пишется во временный файл и переименовывается поверх цели. `webui.json`
  пишется в каноническом виде этого инструмента: отступ в два пробела и перевод
  строки в конце. Это сознательно **не** формат `config.json`, у которого остался
  контракт эталона (`json.dump(..., indent=2)`, без перевода строки в конце),
  потому что его байты сравнивает приёмка.
* **«Сохранить» забирает с собой открытую форму.** Раньше кнопка в заголовке
  отправляла только ключ панели, поэтому поле, не прошедшее через «Применить»,
  выбрасывалось, а уведомление при этом говорило «Сохранено» — владелец поймал это
  на галочке. Теперь каждая панель помечает свою форму правки `id="panel-form"`, а
  кнопка привязана к ней двумя способами, потому что заголовок и форма лежат в
  разных частях DOM: htmx подтягивает поля через `hx-include`, а `form="panel-form"`
  делает то же самое при выключенном JavaScript. У панели в этой единственной форме
  может быть несколько маршрутов. Панель без формы правки (`proxies`, `routes`,
  `system`, `journal`, `tests`, `providers`) сохраняет прежнюю
  самостоятельную кнопку — битая ссылка `form=` перестала бы отправлять её вовсе.
  `/save` применяет форму той же функцией, что и маршрут панели, поэтому они не
  могут разойтись; маршруты панели применяются атомарно (отказ возвращает модель к
  прежнему состоянию), отказ ничего не пишет и сохраняет введённые значения, а
  сохранение без правок отвечает «нечего сохранять» и не плодит снапшот.
  «Перечитать с диска» остаётся непривязанной сознательно: перечитывание и должно
  отбрасывать.
* **Одна модель на процесс.** Состояние (загруженный файл, несохранённые правки)
  живёт на сервере — ровно так Qt-окно было тонкой обвязкой над `model.py`. Две
  открытые вкладки будут молча затирать правки друг друга; блокировок нет и не
  планируется — одна вкладка на экземпляр.
* **Без CDN и без сборки.** htmx отдаётся из `public/vendor/`, поэтому морда
  работает на роутере без интернета, а файлы копируются как есть.
* **Генерация идёт по сохранённому файлу** — тем же `generateConfigFile`, что и
  CLI, — и честно говорит, если в редакторе были несохранённые правки.
* **Системный слой — один модуль.** [`src/system/index.mjs`](src/system/index.mjs:1)
  экспортирует `restartSingBox`, `checkConfig`, `tailJournal`, `testOutbound`,
  `testOutbounds` и `geositeLookup`, и это единственное место,
  которое запускает команды. Всегда `execFile`/`spawn` с массивом аргументов: теги
  вида `🇨🇾 Cyprus - Limassol` ломают командную строку и без злоумышленника.

## Системный слой (этап 3)

Модуль проверяем без sing-box: пути к бинарям приходят из окружения, а тесты
подставляют скрипты-обманки из `tests/fixtures/bin/`.

* **`sing-box check` доказывает меньше, чем звучит.** Проверено на 1.14: он ловит
  неизвестный тип инбаунда и лишние поля, а дубль `listen_port`, ссылку на
  несуществующий тег аутбаунда и опечатку в `dns.final` пропускает с `exit=0`.
  Поэтому надпись в панели — «схема принята», а не «конфиг корректен»: неверная
  надпись и есть то, что уговаривает владельца перезапуститься с конфигом, который
  демон не поднимет.
* **сгенерировать → проверить → перезапустить, именно в этом порядке.** Кнопка
  перезапуска рисуется только после успешной проверки файла на диске, а маршрут
  иначе отказывает. У юнита `Restart=always`, поэтому отвергнутый демоном конфиг
  означает вечный цикл перезапусков и весь дом без сети.
* **Откат — в один клик.** Перед каждой генерацией предыдущий `config.json`
  копируется в `<state-dir>/snapshots/config-<ISO>.json` (хранятся последние 10) и
  возвращается побайтово, с последующим перезапуском.
* **Журнал — снимок, а не живой поток.** Панель один раз запускает `journalctl -u
  <юнит> -n 200 -o json` и рисует последние строки; в запросе передаются юнит и
  минимальный уровень. Один запрос, никакого состояния на сервере и никакого
  процесса после ответа. Живой хвост убран 22.09.2026: `journalctl -f` через SSE
  тянул за собой счётчик потоков, отказ 409 и дочерний процесс, убиваемый по
  `req.on('close')`, а настоящий сценарий — «что-то сломалось, покажи почему», а
  не «слежу за строкками». Структурный вывод сохранён: `-o cat` потерял бы
  уровень. `MESSAGE` — НЕ всегда строка: journald кодирует массивом байтов любое
  значение, в котором есть непечатаемые байты, а sing-box красит
  ANSI-последовательностями каждую строку, поэтому так приходит каждая запись
  демона. Разборщик декодирует массив, снимает ANSI и срезает дублирующий префикс
  `+0000 <дата> <время> <уровень>`, с которого начинается строка sing-box. Любой
  SSE-маршрут отвечает `200` даже при отказе: `EventSource` не переподключается
  после ответа не-200, поэтому массовый тест сообщает «тест уже идёт» событием
  внутри потока.
* **Тест серверов заменяет `live_test`.** `sing-box tools fetch` поднимает свой
  экземпляр, не биндит инбаунды и не трогает работающий демон, поэтому проверка 148
  серверов стоит ноль перезапусков. Массовый прогон ограничен (4 одновременно по
  умолчанию) и отдаёт прогресс через SSE, поэтому не блокирует запрос на минуты.
* **`geositeLookup` — заглушка с человеческим сообщением.** В sing-box 1.14 база
  geosite не ставится, маршруты владельца используют обычные `domain_suffix`, и
  панели для него нет намеренно: отсутствие базы превращается в «база geosite не
  установлена» вместо голого `FATAL`.

## Закреплённый выход, внешний API и сторож

Канал владельца периодически душится DPI: соединения к серверу залипают, и
помогает перезапуск демона — **на тот же сервер**. Выбор сервера не свободен:
часть прокси сознательно прибита к конкретной стране, потому что сервис на том
конце следит за географией входа. `claude-http` закреплён за
`🇨🇾 Cyprus - Limassol`, и инструмент защищает это на двух уровнях.

* **`pinned: true` у прокси запрещает пул.** В форме прокси есть отметка «выход
  зафиксирован»; при ней сохранение, которое оставило бы два и более серверов,
  отвергается текстом «у прокси зафиксирован выход — снимите отметку, если нужен
  пул», и точно так же отвергается включение отметки у прокси, где пул уже есть.
  Список при этом никогда не обрезается молча. В дереве закреплённый прокси виден
  как `[🔒] выход зафиксирован` — без открытия формы, — а рядом поле `note`, куда
  владелец записывает причину. Ядро этот ключ не знает и отбрасывает, поэтому
  `config.json` не меняется; это проверяет тест. Это защита от собственной будущей
  ошибки, а не механизм sing-box: снаружи закреплённый прокси сдвинуть всё равно
  нечем.
* **Внешний HTTP-API — по выбору и только на петле.** Секция `clash_api` в
  `webui.json` по умолчанию выключена. При включении генератор добавляет
  `experimental.clash_api` с `external_controller` и секретом; при выключенной
  настройке вывод побайтово прежний. `external_controller` может указывать только
  на `127.0.0.1` — на роутере по тому же адресу живёт WAN, и открытый API это
  полное управление демоном из интернета, — а секрет берётся из
  `GATEHOUSE_API_SECRET` и никогда из `webui.json`, где он попал бы в снапшоты
  и бэкапы. Включённый API с пустым секретом — отказ с внятным сообщением, как и
  правило про токен выше. Это первое сознательное расхождение с питоновым
  эталоном, который такой блок выдать не умеет.
* **Сторож проверяет через инбаунд.** Он запускает `curl -x http://…` (или
  `socks5h://…` для socks-инбаунда) к локальному инбаунду прокси, потому что это
  та же дорога, по которой ходит приложение: инбаунд → правило маршрута → пул →
  сервер. `tools fetch` проверяет только аутбаунд и пропустил бы проблему на любом
  другом участке. Цель по умолчанию — `https://www.gstatic.com/generate_204`:
  нейтральный эндпоинт для проверки связи, без лимитов, а не `ipinfo.io` с его
  месячной квотой — тот остаётся целью **ручного** теста серверов, где как раз
  важно увидеть город. Цель задаётся на каждый прокси рядом с `watch`; подсказка у
  поля честно пишет размен: адрес сервиса диагностирует точнее, но ставит
  автоматический запрос с выходного IP владельца ровным интервалом. По умолчанию
  этого не происходит.
* **Лестница и предохранители.** После двух подряд неудач закрываются соединения
  **только этого** прокси — через `GET /connections` и `DELETE /connections/<id>`;
  если следующая проверка снова не прошла, перезапускается демон, и лишь при
  включённой второй ступени. Вторая ступень глобальна: она рвёт соединения у всех
  прокси разом, и панель об этом пишет прямо. `api group select` не используется
  вообще — уводить закреплённый прокси на другой сервер это ровно то, чего нельзя
  делать. Предохранители: интервал 10 минут, две неудачи до действия, пауза 30
  минут между действиями одного прокси, не больше трёх перезапусков в сутки и
  дальше «сдаюсь» до сброса владельцем, общий выключатель (при выключенном не
  выполняется ничего, даже для прокси с `watch: true`), и сам `watch: true`,
  выключенный по умолчанию.
* **Сторож не может писать конфиг.** Он живёт в процессе редактора, за границей
  `src/system/`, и его единственные права — закрывать соединения и перезапускать
  демон; настройки он только читает и никогда не пишет `webui.json` или
  `config.json`. Выбранный сервер живёт в конфиге, поэтому сторож, не трогающий
  конфиг, не может изменить выход ни при каких обстоятельствах — тест сверяет
  хеши обоих файлов до и после полного цикла. Каждое решение пишется в журнал
  (сервис пишет в journald) и хранится в истории последних 20 событий в панели: без
  неё сторож превращается в чёрный ящик, который что-то делает ночью. Вторая
  ступень выключена, пока спайк владельца не подтвердит, что закрытие соединений
  без перезапуска связь не восстанавливает; команды для этого спайка — в
  [`techdocs/done_2026_09_14_pinned_exit_and_watchdog.md`](techdocs/done_2026_09_14_pinned_exit_and_watchdog.md).

## Аутентификация и безопасность

* **Не адрес петли без токена — отказ старта.** С этого этапа морда умеет
  перезапускать демон и показывает ключи VLESS, поэтому `GATEHOUSE_HOST` не
  адрес обратной петли вместе с пустым `GATEHOUSE_TOKEN` — это ошибка запуска с
  причиной и обоими выходами, а не строка в логе.
* **Все маршруты за токеном, включая SSE.** `Authorization: Bearer …` или
  `?token=…`; на форму с параметром отвечаем cookie `HttpOnly` и `SameSite=Strict`,
  чтобы `EventSource` панелей мог аутентифицироваться сам. Сравнение сверяет длину
  и использует `timingSafeEqual`.
* **Петля плюс ssh-туннель по-прежнему надёжнее.** По открытому HTTP токен идёт по
  локальной сети без шифрования, поэтому привязка к LAN с токеном — удобство, а не
  защита от прослушивания. HTTPS-терминации в проекте нет намеренно: используйте
  `ssh -L 8080:127.0.0.1:8080 denis@10.95.2.1` или внешний прокси.

## Развёртывание

[`deploy/`](deploy/README.md:1) содержит systemd-юнит, правило sudoers, вариант на
polkit и пошаговый `deploy/README.md`. Ничего оттуда не применяется автоматически.
Код лежит в `/opt/gatehouse`, поэтому в юните включены `ProtectHome=yes` и
`ProtectSystem=strict`. Второе оставляет код нередактируемым для самого сервиса и
при этом не мешает `rsync` владельца: ограничение действует в пространстве имён
юнита, а не в правах на диске. `NoNewPrivileges=yes` ломает `sudo` (setuid),
поэтому он есть только в варианте на polkit — это единственное решение, которое
файлы оставляют владельцу.
`UMask=0027` и `StateDirectoryMode=0700` — не украшение: на роутере umask `0002`, и
на машине есть второй аккаунт с шеллом.

## Формат настроек: `webui.json`

`settings.yaml` заменён на `webui.json`. YAML ушёл сознательно: файл больше не
правят руками, поэтому сохранение комментариев (единственная причина, по которой
в питоновом проекте жил `ruamel`) перестало быть требованием. Файл проверяется
по [`src/schemas/webui.schema.json`](src/schemas/webui.schema.json) через `ajv`
при каждой загрузке.

```json
{
  "version": 2,
  "note": "Reality-транспорт, основной",
  "listen_ip": "10.95.2.1",
  "sources": ["vpnd", "hidemyname"],
  "output_file": "/etc/sing-box/config.json",
  "exclude_from_auto": ["🇷🇺"],
  "log": { "level": "info", "timestamp": true },
  "urltest": { "url": "https://gstatic.com", "interval": "3m", "tolerance": 50 },
  "dns": { "servers": [], "rules": [], "final": "dns-local" },
  "proxies": [
    { "tag": "main", "type": "mixed", "port": 54321, "note": "",
      "servers": ["🇫🇮 Finland - Helsinki 1"] }
  ],
  "routes": {
    "telegram": { "outbound": "🇫🇮 Finland - Helsinki 1",
                  "domains": ["telegram.org", "t.me"] }
  }
}
```

Правила формата:

* **документ один, уровень профилей упразднён:** `version: 2`, ни `profiles`, ни
  `defaults`, ни `active`. Файл старой формы редактор переводит сам и сохраняет
  снимок; ядро такой файл отвергает с сообщением про редактор, чтобы генерация не
  шла по наполовину переведённому документу.
* **`sources` — список имён папок-провайдеров** под корнем источников. Папка может
  держать `links.txt`, `*.conf` или и то, и другое; конфиги туннелей показываются,
  но в `config.json` не превращаются.
* **`note` — комментарий для человека**: и у профиля, и у прокси. Ядро его
  игнорирует, в `config.json` он не попадает.
* **`pinned`, `watch` и `watch_url` у прокси и секция `watchdog` — только для
  редактора.** Ядро их отбрасывает, `config.json` не меняется; правило `pinned`
  обеспечивает модель, а секцию читает сторож.
* **`clash_api` — единственная секция, которая доходит до `config.json`.** По
  умолчанию выключена; при включении превращается в `experimental.clash_api`.
  Секрет намеренно не ключ файла — он приходит из окружения.
* **типы прокси — `socks`, `http`, `mixed`**, заданы в одном месте
  ([`src/core/errors.mjs`](src/core/errors.mjs:1), `PROXY_TYPES`) и повторены в
  `enum` схемы; тест падает, если они разойдутся.
* **схема дополняет ядро, а не заменяет его.** Дубли тегов и портов невозможно
  выразить в JSON Schema, поэтому ловит их только `validate_proxies`.
* `webui.json` и содержимое `sources/` отрезаны `.gitignore`: в них личные ключи и
  списки. Синтетические фикстуры — `tests/fixtures/sources/vpnd/links.txt` и
  `tests/fixtures/tunnel/*.conf`.

## Приёмка по золотому файлу

Побайтовое сравнение с питоновым эталоном удалено 22.09.2026: порту больше не
нужен Python-инструментарий, а эталон не поддерживается. Свойство, которое оно
защищало, теперь держит золотой файл:

* `tests/fixtures/golden/config.json` — побайтовый вывод генератора на фикстурной
  модели (`tests/fixtures/settings.json` + `tests/fixtures/links.txt`);
* `tests/build.test.mjs` требует побайтового совпадения с ним и по-прежнему
  проверяет два инварианта формата — 2704 байта и отсутствие перевода строки в
  конце;
* **намеренное** изменение вывода обновляет фикстуру тем же коммитом, поэтому
  разница видна построчно в ревью, а не всплывает на роутере через неделю.

Фикстуры синтетические и обезличенные: UUID и адреса — заглушки, секретов в
золотом файле нет.

## Заметки о порте

* **Предупреждения — это данные, а не stderr.** Эталон часть проблем печатал
  (маршрут на неизвестный outbound, отсутствующая секция `dns`, непарсящаяся
  ссылка) и продолжал работу. Порт собирает их в массив, который возвращается
  вместе с конфигом, чтобы будущая веб-морда могла их показать; CLI печатает их
  в stderr в формулировках эталона.
* **У ядра своих зависимостей нет.** `src/core/` использует `ajv` и больше
  ничего; редактор добавляет `express` и `ejs`, что задание разрешает, и приводит
  с собой 67 транзитивных пакетов. Ни раннера тестов (в Node 22 есть `node:test`),
  ни TypeScript (типы через JSDoc), ни бандлера.
* **Два канонических формата, и это сознательно.** `config.json` повторяет
  `json.dump(..., indent=2)` побайтово и потому не имеет перевода строки в конце;
  `webui.json` — исходник, который правят и руками, и редактором, поэтому пишется
  с отступом в два пробела и переводом строки в конце. Оба решения зафиксированы
  в [`src/model/storage.mjs`](src/model/storage.mjs:1), чтобы их не «унифицировали»
  позже.
* **Интерактивного пикера нет намеренно.** `pick_proxy`, `filter_and_select`,
  `ask_wqx` и `main()` эталона не портируются, их место занимает будущая
  веб-морда.
* **`curl_test` и `live_test` не вернутся.** `live_test` ради проверки одного
  сервера переписывал `config.json` и рестартовал sing-box — 149 рестартов на
  148 серверов, каждый рвёт все соединения в доме. Проверенная замена
  реализована:

  ```bash
  sing-box tools fetch -c /etc/sing-box/config.json -o "🇨🇾 Cyprus - Limassol" https://ipinfo.io
  ```

  Она завершается за секунду с кодом 0, не трогает работающий sing-box, а
  массовый тест запускает её по серверу с ограничением одновременности. См.
  «Системный слой» выше.
